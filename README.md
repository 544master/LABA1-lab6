# LABA1 — Управление доставкой (вариант 16)

Полный проект: основное приложение + два тестовых проекта. Пересобран
целиком в едином проходе.

## Структура

- `LABA1/` — основное приложение (WinForms, .NET 10)
- `LABA1.Tests/` — модульные тесты (MSTest): DeliveryTests, DeliveryManagerTests,
  BoundaryConditionTests, UITests, EditDeliveryTests
- `LABA1.UITests/` — UI-автотесты (FlaUI): DeliveryFormUITests

## Что изменено относительно исходной версии (лаб. №1)

**DeliveryForm.cs**
- Кнопки «Удалить» и «Обновить статус» были нерабочими (адрес неверно
  разбирался из текста списка) — исправлено переходом на
  `deliveriesListBox.SelectedIndex`.
- Добавлена проверка даты доставки (запрет прошедших дат).
- Добавлена функция редактирования доставки (кнопка «Редактировать»).
- Элементам управления присвоены имена (`Name`) для UI-автоматизации.
- `statusComboBox` переведён со стиля `DropDown` на `DropDownList` —
  так надёжнее работает UI Automation.
- Убран блокирующий `MessageBox` после успешного редактирования — он
  не нёс функциональной нагрузки и мешал автотестам.

**DeliveryManager.cs**
- Добавлен публичный метод `Save()` для сохранения изменений,
  внесённых напрямую в объект `Delivery` при редактировании.

## Перед запуском

1. Откройте `LABA1.slnx` в Visual Studio.
2. Соберите решение (Build Solution).
3. В `LABA1.UITests/DeliveryFormUITests.cs` поправьте константу `ExePath`
   под фактический путь к собранному `LABA1.exe` на вашей машине.
4. Запустите тесты через Test Explorer кнопкой **"Run All"** (важно —
   именно все сразу, тесты зависят друг от друга по порядку, см. ниже).

## Как устроены UI-тесты (LABA1.UITests)

Тесты идут последовательно и работают с одними и теми же 4 заявками —
не создают новые данные в каждом тесте, а редактируют/удаляют то, что
было создано в первом тесте (так же, как при обычной ручной работе,
где данные сохраняются в `deliveries.txt` между запусками):

1. **Test1_CreateFourDeliveries** — создаёт 4 заявки: Ваня (СПб),
   Вася (Воронеж), Дима (Москва), Никита (Екатеринбург).
2. **Test2_EditDimaToSasha** — редактирует заявку "Дима, Москва",
   созданную в Test1, на "Саша, Владивосток".
3. **Test3_UpdateVasyaStatusToDelivered** — меняет статус заявки
   "Вася, Воронеж" на "Доставлен".
4. **Test4_DeleteNikita** — удаляет заявку "Никита, Екатеринбург".

Данные очищаются только перед Test1 (проверка `TestContext.TestName` в
`TestInitialize`) — это гарантирует чистый старт при каждом повторном
запуске всего набора тестов, даже если предыдущий прогон оставил старые
записи в `deliveries.txt`.

## Ограничения проверки в песочнице

Эта сборка готовилась в Linux-песочнице без Windows и без доступа к
nuget.org, поэтому:
- `Delivery.cs` и `DeliveryManager.cs` (без зависимостей от WinForms)
  реально скомпилированы здесь офлайн (`dotnet build`, .NET 8) — без ошибок.
- `DeliveryForm.cs` и оба тестовых проекта собрать в песочнице не удалось
  (нужны `Microsoft.WindowsDesktop.App.Ref`, MSTest и FlaUI из NuGet).
  Код проверен вручную (сигнатуры методов и полей соответствуют друг
  другу, скобки и синтаксис выверены), но реальную сборку и прогон
  тестов нужно сделать в своей Visual Studio.
